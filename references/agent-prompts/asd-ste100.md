# Technical Documentation Standard

Read this reference when creating or revising READMEs, guides, API documentation, architecture documents,
decision records, codemaps, explanatory comments, or docstrings.

## Authority and verification

Follow the project's specified issue of ASD-STE100 Simplified Technical English.
If none is specified, use Issue 9 (January 15, 2025).
Use the official writing rules and dictionary as the authority. This reference is a checklist, not the standard.
If the official reference is unavailable, report that compliance could not be verified and identify the missing reference.
Do not claim verified compliance from a general language review.

Apply the requirement to documentation in the current task. Do not rewrite unrelated documents.
Preserve executable code, identifiers, commands, paths, URLs, literal values, and exact quotations.
Apply the standard to surrounding prose without changing technical meaning.
Do not apply conversational fragments to technical documentation.

## Writing checklist

- Use consistent terminology, clear sentence structure, and explicit instructions.
- Apply the official rules for technical names and technical verbs.
- Use active voice and one instruction per step.
- Put conditions before the instructions that depend on them.
- Keep sentences short and lists parallel.
- Remove unnecessary words and ambiguous pronouns.
- Preserve qualifications needed for accuracy, uncertainty, or safety.
- Verify prose against the applicable writing rules and dictionary.
