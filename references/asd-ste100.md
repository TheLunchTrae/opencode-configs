# ASD-STE100 Simplified Technical English

Shared rules for technical documentation in this repository. Use for writing and
reviewing READMEs, API docs, guides, codemaps, and code comments.

## Sentence structure

- Keep sentences short. Aim for 20 words or fewer. Do not exceed 25 words.
- Write one instruction per step.
- Use active voice.
- Use imperative mood for procedures.

## Word choice

- Use approved dictionary words when possible. Avoid jargon, slang, and contractions.
- Use one term for one concept. Do not use synonyms for the same thing.
- Avoid nominalizations. Use verbs, not noun forms of verbs.
- Do not use ambiguous pronouns. Make references explicit.

## Clarity

- Remove unnecessary words.
- Do not hedge. Use direct statements.
- Keep lists parallel.
- Put conditional words before the instruction.

## Examples

| Not compliant | Compliant |
|---------------|-----------|
| It is important to ensure that the configuration is correctly set up. | Set the configuration correctly. |
| The user should make sure they have the necessary permissions. | Make sure that you have the necessary permissions. |
| This can be done by running the command. | Run the command. |
| Utilize the interface to perform the action. | Use the interface to do the action. |
