# Design response

Read `@agent-prompts/response-formats/common.md` if its guidance was not already supplied.
Use its envelope with these sections under `Result`:

### Requirements and current state

State the supported requirements, existing boundaries, constraints, and assumptions. Cite evidence in `Evidence`.

### Proposal

Describe responsibilities, interfaces, data ownership and lifecycle, failure handling, and relevant security boundaries.
Distinguish existing components from proposed ones. Include a diagram only when it clarifies the design.

### Alternatives and rationale

Explain consequential trade-offs, rejected alternatives, and why the proposal fits the stated constraints.

### Validation and risks

Give acceptance conditions, proposed checks, structural risks, and mitigations. Put unresolved decisions and required
review in `Unresolved items`. A design proposal is neither an independent review nor implementation approval.
